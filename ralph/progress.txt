## Codebase Patterns
- Use `yarn build` after any source change to keep `dist/linter.mjs` in sync (dist/ is committed by design).
- Integration tests live in `tests/integration/<name>/{fixture,expected,args.txt}`. Snapshot new fixtures via `UPDATE_SNAPSHOTS=1 node tests/integration/run.mjs [name]`.
- To snapshot files the linter writes (e.g. `prd.json`), list them in `fixture/extra-snapshots.txt`.
- Check subclasses live in `checks/` and extend `BaseCheck`. They override `lint`, `fix`, and optionally `lintAndFix`. Signatures are now `(file: string, deps: Record<string, unknown>)` — no `entry` parameter.
- `linter-config.json` is loaded and validated in `loadConfig()` in `linter.ts`. Add hard errors for disallowed config fields there so misconfiguration is caught before any check runs.
- `CompositeCheck` is created automatically by the runner when a check config has a `fixWith` block.
- `.linter/` and `dist/*.map` are gitignored; `dist/linter.mjs` is committed on purpose.

## 2026-07-25 - US-001
- Deleted `entries/` and `expanders/` directories (base, file, and json-array variants).
- Removed the `#expander`, `setExpander()`, `expand()`, `supportsInMemory`, and `*InMemory` methods from `BaseCheck`; also dropped the `entry` parameter from `lint`, `fix`, `lintAndFix`.
- Rewrote `AiPromptCheck` to work on a file path directly (reads whole file, writes back via `fs.writeFile` on fixed). Lock key is now `path.relative(repoRoot, file)`.
- Simplified `CustomCheck` env: dropped `LINTER_ENTRY_ID`, `LINTER_ENTRY_SOURCE_FILE`, `LINTER_ENTRY_METADATA`.
- Removed `entry` parameter from `CompositeCheck` and `CrlfCheck` overrides.
- Removed `builtinExpanders` from `registry.ts` and its section from `printHelp()`.
- Rewrote the run loop in `linter.ts` to drop `assertEntrySupported`, `runEntryLint`, `runEntryFix`, and the `byEntry` grouping — checks now run directly against a file path.
- Added a config-load error in `loadConfig()` that fires if any check entry has an `expander` block; the message links to `docs/per-finding-workflow.md`.
- New fixture `tests/integration/config-expander-rejected/` with a config that has an `expander` field; captures stderr + exit 1.
- Files changed: `linter.ts`, `registry.ts`, `checks/base-check.ts`, `checks/ai-prompt-check.ts`, `checks/custom-check.ts`, `checks/composite-check.ts`, `checks/crlf-check.ts`, deleted `entries/*`, deleted `expanders/*`, added `tests/integration/config-expander-rejected/*`, `dist/linter.mjs` (rebuilt).
- **Learnings for future iterations:**
  - The check `entry` parameter and the in-memory (`*InMemory`) API were only used by `AiPromptCheck`. Removing them means AI-based checks operate on whole files now — if per-slice AI review is needed later, it will have to be re-added on top of the fingerprint machinery instead of via expanders.
  - `CustomCheck` no longer exposes entry metadata via env vars; only `LINTER_FILE`, `LINTER_REPO_ROOT`, `LINTER_MODE` remain. Any external scripts that read `LINTER_ENTRY_*` need updating.
  - `builtinRegistry` in `registry.ts` is what the config `export` field looks up. Anything referenced in `linter-config.json` must appear here.
  - The pre-commit hook uses `.git/hooks/linter.mjs` (see `pre-commit`), which is a snapshot — not the current source. `dist/linter.mjs` is what everyone else uses.
  - `path.relative(repoRoot, file)` is now the canonical "identity" of a file across the codebase (lock keys, PRD paths). Reuse it in later steps rather than inventing new key shapes.
