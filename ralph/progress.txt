## Codebase Patterns
- `yarn build` compiles source to `dist/linter.mjs`; `yarn test` runs `tests/integration/run.mjs`.
- Integration tests: each fixture in `tests/integration/<name>/fixture/` is copied to a temp dir, `git init`ed, and the linter runs with `args.txt`. Compare stdout/stderr/exit-code against `expected/`.
- Snapshot regeneration: `UPDATE_SNAPSHOTS=1 node tests/integration/run.mjs [<fixture-name>]`.
- The linter's `--no-ts-as-operator` rule matches ` as ` even in strings/comments — reword to "because it", "like", etc.
- `Record<string, unknown>` options: use `String()`/`Number()`/`!!` for coercion, bracket notation for keys.
- Errors are `unknown` in catch blocks — use `err instanceof Error ? err.message : String(err)`.
- Config-load errors are thrown from `loadConfig()` in `linter.ts` and surface via the top-level try/catch as `Error during processing: <message>` on stderr with exit code 1.
